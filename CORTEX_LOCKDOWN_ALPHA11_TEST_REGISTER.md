## 2. Investigation & Root Cause of Historical Discrepancies

### 2.1 The Discrepancy

### 2.2 Root Cause Analysis

An exhaustive code audit of all test scripts in `scripts/` revealed the following root causes:

1. **Approximation vs Actual Execution Counts**:
   In early development milestones (Alpha 5–Alpha 9), report summary tables utilized estimated round figures (e.g. reporting 30 for Alpha 5, 30 for Alpha 6, and 32 for Alpha 7) rather than querying the exact runtime counters generated by the test runner.
2. **Omission of Foundational Suites in Alpha 10**:
   The Alpha 10 report excluded the two foundational verification suites ([test-lockdown-windows-security.ts](file:///C:/Users/shiva/.gemini/antigravity/scratch/universal-code-platform/scripts/test-lockdown-windows-security.ts) [22 checks] and [test-lockdown-api-integration.ts](file:///C:/Users/shiva/.gemini/antigravity/scratch/universal-code-platform/scripts/test-lockdown-api-integration.ts) [16 checks]), while recalculating milestone estimates as 18, 22, 20, 24, 26, 28, 25, 25, 30, and 26 (totaling 244).
3. **True Physical Execution Reality**:
   When executed directly against Node.js 24 and the actual workspace codebase, the actual physical check counts for each script are:
   - Foundational Windows Security: 22 checks
   - Foundational API Integration: 16 checks
   - Alpha 1 Runtime: 36 checks
   - Alpha 2 Telemetry: 24 checks

## 4. Reconciled Functional Test Categories

Deduplicating regression assertions across milestones reveals eight primary functional test categories:

### 4.1 Category A: Win32 Operating System Hooks & Kiosk Lockdown
- `WIN-SEC-01` through `WIN-SEC-15`: `WH_KEYBOARD_LL` low-level keyboard hook suppression of `VK_LWIN`, `VK_RWIN`, `Alt+Tab`, `Alt+Esc`, `Ctrl+Esc`, `Alt+F4`, `PrintScreen`, `F12`, `Ctrl+Shift+I`.
- `WIN-SEC-16` through `WIN-SEC-22`: Process watchdog blacklist covering OBS Studio, Discord, TeamViewer, AnyDesk, Chrome, Firefox, Edge, Wireshark, Cheat Engine, x64dbg.
- `WDA-01`: Window Manager display capture protection via `SetWindowDisplayAffinity(hwnd, WDA_MONITOR)`.
- `CLIP-01`: Periodic and focus-driven clipboard purging via `EmptyClipboard()`.

### 4.2 Category B: Cryptographic Attestation & Launch Grants
- `AUTH-01`: Deterministic SHA-256 security policy hashing.
- `AUTH-02`: HMAC-SHA256 3-segment JWT launch grant signing and signature verification.
- `AUTH-03`: Cryptographic parameter tamper detection (modifying `sub`, `examId`, or `policyHash` invalidates token).
- `AUTH-04`: Token expiration boundary rejection (expired grants rejected fail-closed).
- `AUTH-05`: Device trust attestation token generation and hardware fingerprint binding.

### 4.3 Category C: Server-Authoritative Emergency Recovery Engine
- `CRYP-01`: Server-only cryptographic pepper provisioning (`LOCKDOWN_SERVER_PEPPER`).
- `CRYP-02`: Canonical message representation binding (`${salt}:${challenge}:${authorizationId}:${otp}`).
- `CRYP-03`: Fail-closed behavior on missing server pepper (throws critical error; zero unkeyed degradation).
- `CRYP-04`: Cryptographic pepper isolation (zero exposure in binary, database, logs, or network payloads).
- `CRYP-05`: 16-byte random salt generation and constant-time equality check (`crypto.timingSafeEqual`).
- `RACE-01`: Concurrency race condition resolution (10 simultaneous redemptions guarantee exactly one winner).
- `RACE-02`: Brute-force auto-burn lockout (3 failed attempts permanently burn the challenge).
- `RACE-03`: Durable cryptographic expiration enforcement (expired challenges rejected fail-closed).

### 4.4 Category D: Distributed Durable Rate Limiting
- `RATE-01`: Proctor issuance rate limit (10 recovery authorizations per 10 minutes per proctor).
- `RATE-02`: Candidate redemption rate limit (5 attempts per minute per candidate).
- `RATE-03`: Workstation hardware rate limit (15 attempts per minute per device ID).
- `RATE-04`: Network IP rate limit (30 requests per minute per IP address).
- `RATE-05`: Atomic SQL UPSERT window sliding and expiration renewal across multi-isolate workers.

### 4.5 Category E: Institutional Pilot Governance & Quota Reconciliation
- `INST-01`: Demonstration institution delineation (demo partners strictly prohibited in production mode).
- `INST-02`: Rejection of unverified institutions in institutional pilot mode.
- `INST-03`: Mandatory documentary evidence document verification (`administrativeEvidenceDoc`).
- `INST-04`: Documentary evidence audit metadata verification (`evidenceVerifiedAt`, `evidenceVerifiedBy`).
- `INST-05`: Dynamic revocation registry (instant independent revocation of institutions, classrooms, exams, candidates, or devices).
- `QUOTA-01`: Dual capacity model (baseline nominal quota of 50 vs hard ceiling of 60 for `CSE276` and 50 for `MPU201`).
- `QUOTA-02`: Mandatory administrative justification and immutable audit logging for quota modifications.
- `QUOTA-03`: Authoritative active candidate session counting (`getAuthoritativeActiveSessionCount()`) with 120-second heartbeat window and ghost session filtering.

### 4.6 Category F: Biometric & Proctoring Telemetry Heuristics
- `PRC-01`: Asynchronous non-blocking telemetry event dispatcher (`TelemetryDispatcher.cs`).
- `PRC-02`: Video canvas frame sampling (160x120) for face absence and multi-face detection.
- `PRC-03`: Sustained audio anomaly thresholding (decibel tracking and spectral vocalization detection).
- `PRC-04`: Hardware disconnection detection (`camera_revoked`, `microphone_revoked`).
- `PRC-05`: Focus loss detection (`window_blur`, `tab_hidden`) and automatic topmost focus re-assertion.

### 4.7 Category G: Physical Workstation Lifecycle Automation
- `WS-01` through `WS-17`: Installation (`install.bat`), registry protocol registration (`cortex-lockdown://`), account authentication, device enrollment, exam launch, hook enforcement, watchdog detection, display affinity, consent modal, heartbeat tracking, offline queueing, reconnection, emergency exit, autosave, submission, teardown, and uninstallation (`uninstall.bat`).

### 4.8 Category H: macOS Physical Hardware Gates
- `MAC-01`: Physical Apple Silicon hardware verification gate (enforces **BLOCKED / NO-GO** until audited on physical Mac hardware).
