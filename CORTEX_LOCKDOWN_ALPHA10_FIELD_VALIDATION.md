### 2.1 Automated Deployment Engine

The native application lifecycle is automated via dedicated deployment scripts in the [installer directory](file:///C:/Users/shiva/.gemini/antigravity/scratch/universal-code-platform/apps/cortex-lockdown-windows/installer/):

### 2.2 Protocol Launch & Argument Sanitization

The application handles launch links generated by the Cortex examination portal:
`cortex-lockdown://launch?token=<jwt>&examId=<id>&candidateId=<id>`

1. **URL Protocol Parsing**: The application extracts the command-line argument, removes the `cortex-lockdown://` scheme prefix, and decodes the launch grant token.
2. **Argument Injection Defense**: The parser strictly rejects invalid characters, shell escapes, and path traversals, accepting only base64url-encoded JWT strings.
3. **Launch Authorization Attestation**: The embedded WebView2 engine loads the examination URL with signed attestation parameters, verifying that the client is not running inside an unverified browser runner.

## 4. Operating System Security Boundaries & Transparent Limitations

Operating system architecture establishes clear boundaries between user-mode application enforcement and kernel-mode security. Cortex Lockdown transparently documents these boundaries:

### 4.1 The Secure Desktop Boundary (`Ctrl + Alt + Del`)

- **OS Architecture**: In the Windows NT security architecture, `Ctrl + Alt + Del` is the Secure Attention Sequence (SAS). It transitions the display immediately to the Winlogon Secure Desktop.
- **Enforcement Reality**: User-mode applications—even running with administrative privileges—are prevented by the Windows kernel from intercepting or suppressing `Ctrl + Alt + Del`.
- **Cortex Mitigation**:
  1. When a user presses `Ctrl + Alt + Del`, the system transitions to the Secure Desktop, causing Cortex Lockdown to lose focus (`WM_KILLFOCUS`).
  2. The native application immediately logs an integrity violation (`focus_lost`).
  3. The proctor dashboard is notified in real time.
  4. If the user launches Task Manager from the Secure Desktop, the Cortex process watchdog detects `Taskmgr.exe` within 500ms and immediately forces topmost focus or triggers exam lock.
  5. In institutional enterprise environments, Task Manager can be disabled completely via Group Policy Object (GPO): `Software\Microsoft\Windows\CurrentVersion\Policies\System\DisableTaskMgr = 1`.

### 4.2 Local Administrator Boundary

- **OS Architecture**: A student operating on a personal device with local administrator privileges can theoretically kill user-mode processes via kernel drivers, command-line tools, or process injection.
- **Cortex Mitigation**:
  1. Server-authoritative session timers: Killing the client application does not freeze the exam clock.
  2. Heartbeat loss detection: The backend proctor console flags any workstation that fails to send heartbeats for > 30 seconds.
  3. Controlled institutional deployment: On university lab computers, student accounts operate as standard non-administrative domain users, preventing process termination or driver injection.

### 4.3 Multi-Monitor Boundary

- **Hardware Policy**: Cortex Lockdown requires a single-display environment (`allowSingleDisplayOnly = true`).
- **Enforcement**:
  1. The application queries `SystemInformation.MonitorCount` via Win32 `EnumDisplayMonitors`.
  2. If `MonitorCount > 1`, the application displays a blocking modal: "Multiple Displays Detected. Please disconnect external monitors to continue the examination."
  3. The exam workspace remains disabled until secondary displays are physically disconnected.

## 6. Enterprise Antivirus & Deployment Policy

### 6.1 Zero Antivirus Disabling Policy

Cortex Lockdown strictly forbids instructing students or institutional administrators to disable antivirus software, turn off Windows Defender, or bypass firewall security. Security software that requires disabling protective operating system controls is unfit for enterprise institutional deployment.

### 6.2 Code-Signing & SmartScreen Elimination Architecture

To ensure seamless installation without Windows SmartScreen warnings or antivirus false-positives:
1. **Extended Validation (EV) Code Signing**: Production binaries must be signed with a commercial EV Authenticode certificate from a trusted Microsoft Root CA.
2. **Microsoft Defender SmartScreen Reputation**: EV certificates establish immediate positive reputation with Windows Defender SmartScreen, suppressing the "Unknown Publisher" dialog.
3. **Enterprise Group Policy (GPO) / Microsoft Intune**: For institutional computer labs, IT administrators deploy the portable package or MSI via Intune with pre-configured application whitelisting and protocol registrations.
